# 정화자 핑 이동 구현 / 클로드 인수인계

작성: 2026-10-14 (한국 시간). 사용자 요청에 따라 코드 구현. 게임 실행 검증은 미실행.

## 동작

- 대상: 플레이어 1의 사용자 핑, 제어 대상은 플레이어 8의 살아 있고 숨겨지지 않은 비건물·비투사체 유닛.
- 시작 병력 생성 전에는 핑 트리거 비활성화. 연출·게임 종료·레이너 사망 중에는 무시.
- 첫 핑 전: 기존 2초 간격 레이너 추종을 유지한다.
- 새 핑: 좌표를 복사해 저장하고, 교전/이동 여부와 관계없이 정화자에게 공격 이동을 한 번 발행한다. 기존 명령 대기열을 대체한다.
- 2026-10-14 변경 (사용자): 핑 후 30초(`PING_HOLD_SECONDS`, 게임 시간) 동안 새 핑이 없으면 핑을 풀고 레이너 추종으로 돌아간다.
- 핑 이후: 자동 추종은 레이너 대신 저장한 좌표를 사용한다. 도착 허용 반경 3(시험값) 안에서는 추가 명령을 주지 않으며, 일반 자동 교전은 가능하다.
- 교전이 끝나고 대기 상태이며 목표에서 멀어진 유닛은 2초 주기에 복귀 명령을 받는다. 교전 중에는 주기적으로 명령을 덮어쓰지 않는다.
- ~~라바사우르와 전쟁광 등 플레이어 1의 병력, 원시 저그 9번은 변경하지 않는다.~~
  2026-10-14 변경: 원시 저그 9번이 라바사우르스 3기를 갖게 되어, 핑·추종이 8·9번을 함께 다룬다 (`gf_rm_AllyArmy`).
  플레이어 1의 병력은 여전히 건드리지 않는다.
- 모든 사용자 핑 종류를 동일한 공격 이동으로 취급한다. 위험/후퇴 핑의 별도 의미는 아직 없다.
- 레이너 추종으로 복귀하는 별도 명령, 막힌 지형 자동 보정, 순간이동은 구현하지 않는다. 막힌 위치를 찍었다면 이동 가능한 곳에 새 핑을 찍는다.

## 코드 위치와 원본 API 확인

`tools/patch_mission01.py`의 `GALAXY_ALLY_BLOCK`:
`gt_rm_AllyPing_Func`, `gv_rm_pingTarget`, 초기화/배치의 핑 트리거 활성화,
`gt_rm_AllyFollow_Func`의 목적지 선택을 변경했다.

게임 원본 선언 사본에서 `TriggerAddEventPing(trigger, int)`, `EventPingPoint()`, `PointGetX/Y(point)` 확인:
https://github.com/SC2Mapster/SC2GameData/blob/master/mods/core.sc2mod/base.sc2data/TriggerLibs/natives.galaxy

기존 공격 이동·유닛 필터 API는 저장소 구현을 재사용했다. 사용자 입력 이벤트를 받으며 스크립트 핑 생성 함수를 추가하지 않는다.
지면 핑과 미니맵 핑 모두 실제 이벤트 전달 및 좌표를 게임에서 확인해야 한다.

## 검증과 빌드

원본 데이터가 있는 환경에서 `python3 tools/build_ccm.py` 실행.
이번 작업 환경에는 최신 이식에 필요한 전체 원본 데이터가 없어 완성 CCM 재빌드는 하지 않았다.
편집기로 맵을 저장하면 직접 삽입한 동맹 코드가 사라지는 기존 제한을 유지한다.

| 조건 | 기대 결과 |
|---|---|
| 첫 핑 전 | 정화자가 기존처럼 레이너 추종 |
| 미니맵/지면에 핑 | 정화자만 해당 위치로 공격 이동 |
| 이전 지점으로 이동·교전 중 새 핑 | 새 목적지로 명령 교체 |
| 도착 후 레이너가 이동 | 동맹은 핑 위치 유지, 마지막 핑에서 30초가 지나면 레이너 추종으로 복귀 |
| 적과 교전 중 주기 이벤트 | 명령을 반복해서 끊지 않음 |
| 적/다른 플레이어 핑, 연출 중 핑 | 목적지와 명령 변화 없음 |
| 시작 전·레이너 사망·게임 종료 | 핑 이동 없음 |
| 정화자 전멸 | 오류 없이 종료 |
| 절벽·막힌 위치 핑 후 유효한 새 핑 | 새 목적지로 갱신, 순간이동 없음 |
| 핑 이동 중 저장/불러오기 | 목적지 및 트리거가 정상 유지되는지 실제 확인 |

자동 검사는 코드 생성/주입과 원본 보존 범위까지만 의미한다. Galaxy 컴파일 성공이나 실제 이동 성공을 뜻하지 않는다.

자동 검사 결과: Python 문법 검사 통과. 업로드된 실제 미션 스크립트에 LF/CRLF 두 방식으로 주입하여 이벤트 1회 등록, 기존 본문 보존, 재주입 거부를 확인했다.
