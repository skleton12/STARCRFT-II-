# Claude 인수인계 — 3번 맵 공허의 유산 계열 태양 광선

> 원작 능력이 무엇인지에 대한 조사는 [태양의 창·정화 광선 원작 조사](research/solar_lance_and_purifier_beam.md)를 먼저 읽는다. 아래 문서는 기존 모드 구현 인수인계이며 원작 능력 조사 자체를 대신하지 않는다.


2026-10-17 사용자 요청: “공허의 태양 광선 내용 클로드에게 알려줘”. 이 문서로 합의 내용과 현재 구현을 전달한다. 구현 담당은 Claude이며, 이번 인수인계는 문서만 추가한다.

## 사용자와 합의한 진행

**정화자가 남서쪽 적 기지를 태양 광선으로 먼저 공격·정리 → 정화자 병력 소환과 원시저그 투하 → 동맹 기지 확보·건설 → 레이너 지원.**

- 사용자가 3번 맵 이미지에 표시한 노란 X 두 곳은 지원군 투하 및 기지 건설 위치다. 현재 구현상 본진 대응점은 (28.5,29.5), (42.5,29.5)다.
- 플레이어가 먼저 그 적 기지를 모두 청소해야만 동맹이 등장하는 흐름으로 바꾸지 않는다. 사용자는 **동맹이 그 적 기지를 정화하고 지원하는 것**에 동의했다.
- 정화자 병력은 협동전 피닉스·카락스만, 피닉스 중심으로 구성한다. 광선 연출의 출처와 병력 구성의 출처는 별도로 관리한다.
- 최초 확보 때 한 번 사용하는 방향은 앞서 제안했고 현재 코드도 한 번 실행된다. 매 증원마다 광선을 반복하거나 카락스 패널 전체를 도입하라는 지시는 아니다.
- 범위·피해량·대기 시간은 구현 시험값이다. 사용자가 정확한 수치를 확정한 것으로 표기하지 않는다.
- 아군·주민·자원은 진입 공격의 피해 대상에서 제외하는 방향을 유지한다. 영구 무적이나 적 전체 자동 삭제로 확대하지 않는다.

## “공허의 태양 광선”과 실제 리소스 구분

대화에서 사용한 이름은 태양 광선이다. 현재 선택한 리소스는 공허의 유산/협동전 아둔의 창 계열 **Solar Lance(태양의 창)**의 강화 모델이다.

| 항목 | 현재 ID/경로 |
|---|---|
| 모드 모델 ID | `RM3_SolarLance` |
| 실제 M3 | `Assets\Effects\Protoss\SOA_SolarLance_Upgrade\SOA_SolarLance_Upgrade.m3` |
| 모드 피해 효과 | `RM3_SolarDamage` (`CEffectDamage`, `DU_WEAP` 상속) |
| 진입 함수 | `gt_m3_Arrive_Func` |
| 최초 시작 제어 | `gf_m3_Start`, `gv_m3_started` |

**Solar Lance와 Purifier Beam(정화 광선)은 다른 능력이다.** 현재 모델을 정화 광선 패널 능력 전체나 공허 포격기 공격 구현으로 보고하지 않는다. 원작 태양 에너지·사령관 레벨·패널 제어 체계는 이식한 상태가 아니다.

## 실제 배포본 확인 — 0.3.4 기준

조회한 커밋: `2f1725841e46d17fee4e75ce0860bcf921843ab7`. 기준 브랜치 `claude/lucid-franklin-ed0eko`의 커밋 제목은 `CCM 0.3.4: mission 3 allies follow the co-op building reference`다. 해당 커밋의 `releases/RaynorMercs_WoL_CCM.zip` 내부 metadata가 0.3.4임을 확인하고, 실제 ZIP의 스크립트·효과·모델을 읽었다. 빌드 템플릿만 보고 최신 적용 상태로 추정하지 않았다.

현재 동작 순서:

1. 시작 함수 이후 게임 시간 12초 대기.
2. 진입 안내와 시야 공개 후 3초 대기.
3. 정화자 10번 소유의 숨긴 임시 수정탑을 피해 출처로 사용.
4. `pulse=0..11` 동안 0.5초 간격으로 광선 모델을 만들고 제거한다. 위치는 `(20 + pulse*2.5, 30)`이다.
5. 각 회차마다 적 플레이어 2~5의 `(35,31)` 중심 반경 20 안에 있는 살아 있는 유닛에 `UnitDamage`를 적용한다.
6. 회당 기본 피해는 250이다. 감면·방어력·이동을 무시한 단순 표기상 최대 합은 3000이지만, 실제 피해와 전멸을 보장하는 값은 아니다.
7. 임시 피해 출처를 제거하고 주변 점막을 지운 뒤 일꾼이 등장한다.
8. 수정탑 건설 16초 후 첫 정화자 소환·원시저그 투하를 시작하고 본진·생산 건물 건설을 진행한다. 이후 지속 지원으로 이어진다.

0.3.4 ZIP에서는 원시저그 건설이 `DehakaHatchery`·`DehakaBarracks`, 일꾼이 `DehakaDrone`으로 바뀐 것도 확인했다. 0.3.1의 일반 부화장·산란못 상태를 최신 배포본에 그대로 적용해 설명하지 않는다.

## Claude가 확인·보완할 사항

1. **광선 외형과 실제 피해 범위가 일치하지 않는다.** 모델은 선을 따라 이동하지만 피해는 회차마다 반경 20 전체에 들어간다. 현재는 모드용 지역 정리 연출이며 원작 Solar Lance의 선형 타격을 그대로 이식한 것이 아니다. 광선 경로 주변만 타격할지, 넓은 지역 정화로 유지할지는 합의한 진입 의도를 보존하면서 구현·문서에 명확히 남긴다.
2. **남은 적 확인이 없다.** 12회가 끝나면 잔존 적·건물 수와 관계없이 건설로 넘어간다. “정리 후 기지 확보”라는 합의와 다를 수 있으므로 잔존 적 처리와 건설 시작 조건을 확인한다. 무한 광선·무한 대기·영구 무적을 임의로 추가하지 않는다.
3. **실제 모델 재생을 확인해야 한다.** `CreateModelAtPoint`와 `AnimPlay Attack Attack NonLooping`만으로 해당 M3가 의도대로 보이는지 미확인이다. 화면에 안 보여도 피해만 들어가는 상태를 정상으로 보고하지 않는다. 설치 클라이언트의 모델·텍스처 참조도 확인한다.
4. **원본 임무에 미치는 영향을 확인한다.** 숨김·잠복·무적 상태의 적, 부화장 파괴 업적/목표, AI 재건 및 진입 중 새 공세에 대한 동작을 점검한다. 적 전체의 기지나 주민을 정리 범위에 넣지 않는다.
5. **재실행 방지를 유지한다.** 최초 진입과 90초 반복 증원을 분리하고, 저장/불러오기나 기지 재건이 최초 광선을 다시 호출하지 않도록 확인한다.

위 항목은 코드/파일 검토 결과이며 게임에서 재현·해결을 확인한 기록이 아니다. 이번 인수인계에서는 스크립트·맵·배포 ZIP을 변경하지 않았다.
