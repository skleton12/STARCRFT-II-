# 0.2.20 — 협동전 드롭포드와 주민 중립 관계

사용자 요청: 원시 저그가 소환될 때 협동전 버전으로 떨어지게 하고, 중립 주민과 적대되는 이유를 확인한다.

## 확인·변경

- 0.2.19 모델은 군심용 `Assets\Effects\Zerg\ZergDropPodEx1\ZergDropPodEx1.m3`였다.
- SC2Mapster/SC2GameData starcoop ModelData의 ZergDropPod 정의에 맞춰 `Assets\Effects\Zerg\ZergDropPod_AC\ZergDropPod_AC.m3`로 바꿨다. 협동전 정의처럼 기존 모델 사운드 이벤트 두 개도 제거했다. 착지 피해 효과나 새로운 전투 효과는 추가하지 않았다.
- 주민은 3번 플레이어인데, 기존 지원군 초기화는 반란군(4번)만 8·9번 지원군과 중립으로 설정했다. 3번과 8·9번의 관계 설정은 누락되어 있었다. 이것이 확인된 동맹 설정 결함이며 사용자 증상의 런타임 원인 확정은 게임 재시험이 필요하다.
- 초기화에서 3→8, 8→3, 3→9, 9→3을 모두 명시적으로 중립으로 설정했다. 적 플레이어 2·5, 레이너 1, 반란군 4 및 원래 구출 진행은 유지한다.
- 이번 협동전 변경은 드롭포드 외형 연결이다. 지원 유닛을 다른 카탈로그 ID로 교체하거나 데하카 성장 체계를 추가하지 않았다. 투하 위치·3초 후 병력 생성·90초 반복·인구수 보류 기준은 유지한다.
- 1번 미션은 이미 각 주민 진영과 지원군을 중립으로 설정하고 있어 변경하지 않았다.

재현: `python3 tools/patch_coop_pod_neutral.py 입력_0.2.19.zip 새폴더/RaynorMercs_WoL_CCM.zip`.

## 검사

CRC, XML 37개 파싱, metadata·2번 미션 mapscript·modeldata만 변경, 중립 설정 네 줄의 양방향 연결, 나머지 스크립트 동일성, 다른 모델·전체 배치·1번 미션 보존, 중복 패치 거부를 검사했다. 기존 풍부한 자원·매장량 증가·4→3→1 소환·정화자 수정탑 연결을 유지한다.

미실행: Galaxy 컴파일, 게임/에디터 실행, 실제 낙하·착지 애니메이션 시점과 M3/텍스처 해석, 주민과 지원군의 실제 상호 공격 여부. 이전 저장 게임의 초기화가 다시 실행된다고 가정하지 않으며 새 미션으로 재시험한다.
