# 정화자 수정탑 시험본 0.2.17

사용자 요청: 0.2.16의 지원 수정탑을 정화자 외형으로 변경.

기준은 사용자가 첨부한 `RaynorMercs_WoL_CCM.zip`이다. ZIP 내부 metadata 버전은 0.2.16이며 CRC 검사를 통과했다. 원격 브랜치 최신 e46a637은 진행 기록만 추가했고, 원격 코드·맵은 이 전달물과 동기화되지 않았다.

## 변경

- `tools/patch_purifier_pylon.py 입력.zip 출력.zip`으로 재현한다. 기존 출력을 덮어쓰지 않는다.
- 2번 미션 ModelData에서 기존 `Pylon`, `PylonBirth`, `PylonDeath`의 모델 경로만 정화자용으로 덮어쓴다. 기존 액터·유닛은 복제하지 않는다.
- 계정 보상에 따른 원래 Pylon 액터의 외형 교체도 정화자로 유지하도록 `PylonXPR`·`PylonXPRDeath` 모델 경로를 같은 외형으로 지정한다.
- SC2Mapster/SC2GameData의 starcoop `Fenix_Purifier_COOP` SkinData가 지정하는 `Pylon_Purifier_COOP`, `Pylon_Purifier_WarpIn`, `Pylon_Purifier_Coop_Death`를 사용한다. 해당 ModelData의 Building/BuildingDeath 기본 경로 토큰을 해석해 경로를 지정했다.
- metadata 버전은 0.2.17이다. 시험본이며 게임 확인을 마친 버전이 아니다.

기존 스크립트는 바꾸지 않았다. 적 5기 처치 조건, 수정탑 생성 횟수·위치, 건설 16초, 완공 후 대기 5초, 지원군·집결·드롭포드·고용소는 첨부본 그대로다. 4→3→1 묶음 소환 변경은 포함하지 않았다.

## 검사 및 한계

입출력 ZIP CRC, 전체 XML 파싱, 변경된 엔트리가 metadata와 2번 미션 modeldata 두 개뿐임을 검사했다. 기존 모델 항목 보존, 다섯 모델 경로 연결, 스크립트 동일성, 중복 패치 거부도 검사했다. 입력 파일은 보존했다.

M3·텍스처는 설치된 게임의 기본 리소스에 의존하며 ZIP에 새로 포함하지 않았다. 이 환경에는 게임 리소스와 SC2 실행기가 없어 해당 경로의 실제 파일 해석, 렌더링, 건설·완공·파괴 애니메이션은 미검증이다. 카탈로그 경로가 맞는 것과 게임에서 리소스를 찾을 수 있는 것은 별개이므로 외형 문제 해결을 확정하지 않는다.

재시험: 기존 0.2.16과 별도로 시험 ZIP을 적용해 새 미션을 시작하고, 적 정리 후 수정탑 1개가 정화자 외형으로 건설되는지, 16초 뒤 완공되고 5초 후 병력이 나오는지 확인한다. 기존 저장 게임으로 새 모델 데이터가 적용된다고 가정하지 않는다. 건설 중·완공 후·파괴 시 오류 모델이 보이면 해당 장면을 구분해 기록한다.
