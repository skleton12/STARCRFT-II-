# 4번 이후 비선형 진행 설계 (Claude 제안 + 사용자 결정, 2026-10-17)

사용자 지시 (2026-10-17): "4번 이후로는 사람들이 어디 갈지 알 수 없기 때문에 이건 너가 잘 구성해 줘야 됨."
3번(Zero Hour) 뒤에는 임무 순서를 플레이어가 고른다 (docs/missions/campaign_order.md).
그래서 4번부터의 맵은 **'앞에서 무엇을 했는지' 가정하지 않는다.** 아래는 그 원칙과 구현 방식이다.
사용자 결정은 5장에 적었다 (2026-10-17). 1~4장은 Claude 제안이다.

## 1. 가정하지 않는 것

| 하면 안 되는 가정 | 대신 |
|---|---|
| "이 임무 전에 X 임무를 깼으니 유닛 Y가 있다" | 원작 캠페인의 유닛 해금 상태를 그대로 쓴다. 생산 버튼·용병 바꿈은 원래 버튼 조건을 유지한다 (CatalogFieldValueSet은 생산 칸만 바꾸고 해금 조건은 건드리지 않음) |
| "임무 번호가 크면 적이 세다" | 적 강화는 7-1 규칙(난이도·종족)만. 진행도 보정을 넣으면 '끝낸 임무 수'로 한다 (결정 필요 ②) |
| "앞 임무에서 연구했다" | 미션 내 연구는 임무마다 처음부터다 (원작과 같음). 히페리온 무기고 구매는 원작 캠페인 방식을 유지한다 (4장 보류 그대로) |
| "동맹이 이미 등장했다" | 동맹 등장 설명(부관 안내)을 임무마다 짧게 넣는다. 첫 등장인지 판단하지 않는다 |
| 대사·연출이 특정 순서를 전제 | 원작 대사·연출만 쓴다. 모드 대사는 순서와 무관한 문장으로 쓴다 |

## 2. 공통 묶음 — 모든 임무 맵에 똑같이 넣는 것

지금까지는 임무마다 build_v03xx.py로 따로 고쳤다. 4번부터는 **공통 묶음 도구** 하나를 만들어 모든 임무 맵에 같은 내용을 넣는다. 어느 순서로 가도 같은 규칙이 보이게 하기 위해서다.

1. **용병 생산 바꿈표** (docs/research/wol_merc_mapping.md): 병영·군수공장·우주공항의 생산 칸을 플레이어 1만 용병으로. 해금 안 된 유닛은 원래처럼 버튼이 안 나온다.
2. **미션 내 연구 묶음**: 3번에서 만든 것(전투 자극제 한 줄, 전투 방패, 레이저 조준, 보급 벙커 해금, 건물 장갑)을 공통으로. 대상 유닛이 해금 안 됐으면 그 연구 버튼도 안 보이게 원래 조건에 묶는다.
3. **동맹 모듈**: 정화자·원시저그 플레이어 슬롯, 협동전 외형, 명령 불가, 핑 30초, 자동 전투, 병력 상한, 자원 수입. 기본 방식은 결정 필요 ①.
4. **적 강화 7-1**: 맵의 적 종족을 읽어서 저그는 물량, 테란·프로토스는 능력치.
5. **규칙 검사**: 번역 3-1, 레벨 규칙, 종족, 모델 경로, 연결 — check_release.py 그대로.

임무마다 다른 것(동맹 배치 좌표, 자원 위치, 대기 위치, 적 증강 위치)만 임무별 설정 파일에 둔다.

## 3. 진행도 확인 방법 (기술)

맵은 자날 스토리(LibertyStory)에 의존하므로 캠페인 라이브러리 함수를 쓸 수 있다.
- 끝낸 임무 수: `libCamp_gf_CountMissions(libCamp_ge_MissionStatus_Completed)`
- 특정 임무 완료: `libCamp_gf_MissionStatusCheck(맵ID, libCamp_ge_MissionStatus_Completed)`
원작 해금 조건도 이 둘로 짜여 있다. 진행도 보정이 필요하면 이 값만 쓴다.

## 4. 시험 방법

같은 맵을 '이른 진행'(완료 3~4개, 해금 유닛 적음)과 '늦은 진행'(완료 10개 이상)으로 각각 한 번씩 해 본다.
- 이른 진행: 동맹·연구가 없는 유닛을 가리키지 않는지, 클리어 가능한지
- 늦은 진행: 너무 쉽지 않은지

## 5. 사용자 결정 (2026-10-17)

① 동맹 기본 방식 (사용자 확정): 4번 이후 플레이어가 **정화자 관문 최대 3개, 원시저그 원시 감시자 최대 3개**를 지을 수 있게 한다. 동맹 생산 거점이 수정탑 → 관문으로 바뀐다 (관문은 원작처럼 수정탑 동력이 필요하므로 수정탑 건설은 남긴다 — 구현 때 확인). 원시저그는 0.3.35처럼 감시자 알 생산. 일꾼이 레이너 기지에 내려오는 3번 방식, 자기 자원·인구 100·명령 불가는 그대로 이어 쓴다 (구현 전 세부는 4번 작업 때 확인).
② 진행도 보정: 하지 않는다 (사용자 확정). 적 강화는 7-1(난이도·종족)만.
③ 공통 연구 묶음: 4번 이후 모든 임무에 넣는다 (사용자 확정). 대상 유닛·건물이 해금 안 됐으면 버튼이 안 보이게 한다.

## 6. 4번 = 갈림길 (사용자 설명, 2026-10-18)

사용자: "4번부터는 선택적 이동이라 불곰 가는 사람도 있고 화염방사병 가는 사람도 있다."
3번을 끝내면 THanson01(The Evacuation, 화염방사병 해금)과 TTychus01(Smash and Grab, 불곰 해금)이 함께 열린다.
- 어느 쪽을 먼저 가든 다른 쪽은 그 다음 임무가 된다. 그래서 The Evacuation 맵은 '불곰(망치 경호대)이 있을 수도, 없을 수도' 있고, Smash and Grab 맵은 '화염방사병(악마의 개)이 있을 수도, 없을 수도' 있다.
- 두 맵 모두 1장 원칙대로 해금 상태를 그대로 따른다. 망치 경호대·악마의 개 생산 바꿈은 원작 버튼이 열려 있을 때만 보인다.
- 공통 연구 묶음도 같다: 대상 유닛이 없으면 버튼이 안 보인다.
- 사용자 확정 (2026-10-18): 불곰 임무(TTychus01)부터 만든다. The Evacuation은 그다음.
- 필요한 것: 두 원본 맵 파일(THanson01, TTychus01). 저장소에는 아직 TRaynor03까지만 있다.

## 7. 불곰(망치 경호대) 기술실 연구 (사용자 결정, 2026-10-18) — 4번부터 공통 연구 묶음에 넣는다

사용자: "불곰 업그레이드도 기술실에", "셋 다, 단 무기고 업그레이드 제외", "충격탄 → 강화로 한 줄".
| 버튼 | 내용 | 원본 | 비용·시간 (원본 데이터) |
|---|---|---|---|
| 1줄 1단계 | 충격탄 (맞은 적 감속) | 자날·멜리 PunisherGrenades | 100/100·80초 |
| 1줄 2단계 | 억제탄 (강화 충격탄, 같은 자리에서 교체) | 협동전 NovaConcussiveShells | 100/100·60초 |
| 별도 | 자기가속 탄약 | 협동전 MarauderMagrailMunitions | 150/150·90초 |
| 별도 | 파편탄 (2026-10-18 사용자: 무력화탄 대신) | 멩스크 협동전 이지스 근위대 2등급 파편 — 진급 능력을 '모드에서 재설계한 연구'로 | 100/100·60초 |
- 히페리온 무기고에서 사는 불곰 업그레이드(동역학 거품·입자 분열기 등)는 연구로 넣지 않는다.
- 해석 확인 필요: '셋 다'를 '충격탄 줄 + 자기가속 탄약 + 무력화탄 = 버튼 셋'으로 읽었다. 무력화탄과 충격탄 감속이 겹치면 중첩하지 않게 한다 (5장 원칙).
- 망치 경호대가 해금 안 됐으면(불곰 임무 전) 버튼이 안 보인다. 불곰 임무에서는 임무 중에 해금되므로 원작 해금 흐름을 따른다.

## 8. 정화자 차원 관문 (사용자 확정, 2026-10-18)

사용자: "4번 미션부터는 정화자 차원관문 건설 가능하게", "3개까지".
- 5장 ①의 '정화자 관문 최대 3개'를 **차원 관문(WarpGate) 최대 3개**로 바꾼다. 탐사정이 짓는다.
- 정화자 병력은 차원 관문에서 소환한다 (프로토스 = 소환, 원시저그 = 생성 원칙 그대로). 소환 위치는 수정탑 동력장 안 (원작 차원 관문 방식, 구현 때 확인).
- 외형: 협동전 정화자 관문 모델(`Gateway_Purifier_COOP`, 사망 `WarpGate_Purifier_Coop_Death`)을 쓴다. 차원 관문 상태의 전용 모델 유무는 구현 때 원본에서 확인한다.
- 원작 차원 관문은 관문을 지은 뒤 변환하는 건물이다. 바로 차원 관문으로 지을지, 관문 → 변환으로 할지는 구현 때 정한다 (Claude 제안: 바로 차원 관문으로 지어 단계를 줄임).
